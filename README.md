                                                                yolo.py
This code trains a YOLOv8m model in two stages using transfer learning on a GPU-enabled setup. In Stage 1, the backbone is partially frozen (freeze=10) and trained for 50 epochs with an image size of 1024 and batch size of 8, using the AdamW optimizer with an initial learning rate of 0.001, a final learning rate factor (lrf) of 0.01, weight decay of 0.0005, and 3 warmup epochs; all data augmentations are explicitly disabled. In Stage 2, the best weights from Stage 1 are loaded and the full network is unfrozen (freeze=0) for fine-tuning up to 1000 epochs with a lower learning rate (0.0001 to 0.001), 2 warmup epochs, and the same optimizer and batch settings, again without augmentation. Training uses mixed precision (amp=True), runs on GPU (device=0) with 8 workers, saves checkpoints periodically, and organizes outputs into specified project folders.

                                                      yolo_gt.py -  Combined Images:
This part of the code uses a trained YOLOv8m model to run inference on validation images and visually compare predictions with ground truth annotations. For each image, the model predicts bounding boxes at a low confidence threshold, and the predicted boxes are drawn along with statistics such as object count, bounding box sizes (mean, min, max), and an estimated pixel-to-nanometer scale. Simultaneously, the corresponding YOLO-format label file is read, converted into pixel coordinates, and ground truth boxes are drawn on a separate copy of the image. Both predicted and ground truth images are then concatenated side-by-side and saved, allowing direct visual comparison of detection performance for a limited number of samples.

                                                    Confusion Matrix and Evaluation:
In the second part, the trained model is evaluated on the dataset using built-in validation, computing key metrics such as precision, recall, mAP@0.5, and F1-score at specified confidence and IoU thresholds. The code extracts the confusion matrix produced by the detector, interprets true positives (TP), false positives (FP), and false negatives (FN), and verifies metric calculations manually. It then visualizes results using a custom 2×2 confusion matrix (excluding true negatives, which are not meaningful in object detection) and a bar chart of performance metrics. The final evaluation plot is saved to disk, providing both numerical and visual insight into the model’s detection quality. The confusion matrix and model metrics are uploaded in project_results.pdf. Precision: 94.3, Recall:67.3, mAP@0.5: 82.5, F1: 78.6, so far, work is still ongoing.


                                                            trial_model_one.m
This CNN isdesigned for small image inputs (128×128×3). It begins with an input layer followed by two convolutional blocks: the first uses 16 filters and the second 32 filters (both 3×3 with same padding), each followed by a ReLU activation and 2×2 max pooling to progressively extract features and reduce spatial dimensions. The extracted features are then passed directly to a fully connected layer that maps them to the number of output classes, followed by a softmax layer for probability distribution. The final classification layer incorporates class weights to handle class imbalance during training. Overall, it’s a lightweight CNN with two feature-extraction stages and no deep stacking or dropout, suitable for basic image classification tasks. It is a 2 layer custom CNN on Matlab. The model is intentionally built shallow and simple, since the dataset it was trained and validated on was very small(116-Aggregate images, 93-Control images) and binary classification task was rather simple and straight-forward. We did not require millions of feautre extraction and a higly complex non-linear space for this classification task, where other pretrained models would have been more harmful than helpful and caused overfitting.

                                                              try_count_two.m
Uses traditional image processing methods, for detecting and counting aggregates. The image is read using imread and displayed, and an interactive loop with ginput lets the user click on pixels to inspect their RGB intensity values and input a threshold value(mv). The RGB channels are separated into R, G, B, and the green channel is visualized since the objects of interest are prominent there. A binary mask (BW) is created using three logical conditions: low red, high green, low blue for isolating green fluorescent objects of interest in the images based on mv value. The binary image is cleaned using 'bwareaopen' to remove small noisy regions (objects with fewer than 5 pixels). Connected components (bwconncomp) are computed to identify distinct objects (aggregates). 'regionprops' extracts bounding boxes for each detected object. Finally, the bounding boxes are overlaid on the image to visualize detected aggregates and display their count. This code was used to develop the gt images for visual comparison of traditional image processing with model prediction.
